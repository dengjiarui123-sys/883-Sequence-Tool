# Video Sequence Packer · 第一期产品制作说明

> 本文是**独立产品**的实现合同：从 AI / 绿幕视频抽出序列帧，抠透明、整理工作集、导出 ZIP 散图或 Sprite Sheet。  
> **不要**写进现有 Unity Spritesheet Tuner（FrameTest）仓库。两套工具先分开做，合并是后续课题，见第 12 节。  
> 本文自包含：拷到新仓库即可开工。不要求阅读 Tuner 第一期 / 第二期文档才能实现本工具。

交互与能力对齐参考产品 FramePacker 的「抽帧 → 编辑整理 → 导出」三步，但算法与工程文件格式自研，禁止把参考产品的源码、WASM 或 `_FP.html` 工程包拷进本仓库当实现。

---

## 1. 产品是什么

第一期做**本地网页工作台**（浏览器打开，素材不上传到云）。专门处理「视频 → 可用序列帧」这一段，面向绿幕 / 纯色底的 AI 角色动画。

用户闭环：

1. 上传视频，裁剪画面、框选时间、设定抽帧帧率，抽出一串 PNG。
2. 在胶片条工作集里点选单帧，用取色 + 容差 + 边缘清除把背景换成透明；确认后把同一套操作批量回放到工作集。
3. 减帧、寻找循环方案：都只改胶片条的**选中 / 未选中**，不直接删帧；用户再决定是否移出工作集。
4. 导出：ZIP（每帧一张图打包）或 Sprite Sheet（只出总图，格子等大，类似 `Testspritesheet.png`）。
5. 工程可保存、刷新后恢复。

第一期交付的是「抽得出来、抠得干净、选得明白、导得出去」的工作集。不切片、不对齐脚底、不写 Unity。那些仍由 Spritesheet Tuner 负责。

## 2. 完成定义

第一期完成，当且仅当下面全部成立。不要把「能播视频」或「能截一张图」当成完成。

1. 能在 Chrome / Edge 中打开本地页，选择常见 mp4（H.264）或 webm，预览播放与拖动时间轴。
2. 能框选裁剪区域、设定起止时间与抽帧帧率（至少 1–30 fps），显示预估帧数；点「开始提取」后得到工作集胶片条。
3. 胶片条每帧可点选进入编辑器。编辑器至少提供：**换色变透明**（画布取色、容差、边缘清除、棋盘格预览、应用 / 取消）。
4. 对单帧确认后的操作可**批量应用到当前工作集的全部选中帧**（回放同一条操作记录，不是再让用户点 81 次）。
5. 胶片条有且必须有两态：**选中（在工作集内）** / **未选中（仍可见，变暗、无勾）**。减帧与「裁剪到循环区间」只改两态，禁止直接从列表里物理删除。
6. 减帧：每 N 帧留 1 帧，可选留每组第 1 张或最后 1 张；确认前显示预计保留 / 剔除数量。
7. 寻找循环帧：基于自相似矩阵给出**不少于 1 个、建议 3–5 个**方案；每个方案展示帧数、平滑度、覆盖率、帧范围；可预览该方案循环；选用后只把范围内的帧标为选中。
8. 用户可对未选中帧执行：重新选中、全部恢复、**移出胶片条**（这时才物理删除或移出列表）。
9. 导出 ZIP：仅选中帧，每张独立 PNG，按序号打包下载。
10. 导出 Sprite Sheet：仅选中帧，等大 cell 拼成一张（或在图集边长不够时多页）总图；**不附带散图**。导出分辨率必做；格内缩放、偏移、透明填充必做（见第 9 节）。
11. 保存工程后刷新页面，视频不必保留，但工作集像素、选中态、已应用的操作、导出参数都还在。
12. 权威 JSON 不含盘符绝对路径、`Downloads`、Unity `Assets/`。

未完成的例子：抽帧后只能看视频不能点单帧；换色只能改当前一张且不能批量；减帧或找循环直接删文件；循环只给一个分数不给方案列表；导出只能原尺寸截图、不能指定 256×256 格子；Sprite Sheet 格子尺寸不统一；把本工具写进 Tuner 的 `tools/editor`。

## 4. 用户流程

```text
上传视频
  → 预览；拖裁剪框去掉左右黑边
  → 设定起止时间、抽帧帧率，看预估帧数
  → 开始提取 → 进入胶片条工作集（默认全部选中）
  → 点一帧打开编辑器
  → 换色：点绿幕，调容差与边缘清除，预览棋盘格，应用
  → 批量应用到工作集
  → （可选）减帧：未选中的帧变暗，仍留在条上
  → （可选）寻找循环帧：选一个方案，范围内选中、范围外未选中
  → 用户决定：移出未选中 / 改回选中 / 再减一次
  → 导出 ZIP 或 Sprite Sheet（先定分辨率，再调格内缩放与偏移）
  → 保存工程
```

建议默认快捷：

- 空格：预览播放 / 暂停（抽帧页播视频，整理页播选中帧）。
- 胶片条单击：选中该帧并作为当前帧；双击或「编辑」进入编辑器。
- Delete：若焦点在胶片条，将当前帧标为未选中（不要直接物理删除，除非在「移出」确认框里）。

## 5. 界面分区

三个主步骤必须能来回看状态（已完成步骤打勾），不要做成抽完就丢掉视频设置、导完就丢掉工作集。

### 5.1 步骤一：帧提取

左：视频预览 + 裁剪矩形（可拖边、拖角）。右：文件名、分辨率、时长、时间范围双端点、抽帧帧率滑杆、预估帧数、开始提取。

提取中显示进度（已抽出 / 总数），可取消。取消不得留下半套脏工作集；要么回退到提取前，要么明确「保留已抽出的 N 帧」。

### 5.2 步骤二：编辑与整理

两个子页签：**编辑** | **整理**。共享同一条胶片条数据。

- **编辑**：网格胶片条（每帧缩略图 + 序号）。点一帧打开编辑器（独立窗口或全页均可）。编辑器最小工具：换色（必做）。加分：选区、填充、橡皮（还原到抽出原图，不是画成透明色——若做不到，第一期橡皮可简化为「把像素 alpha 置 0」，但须在 UI 写明）。
- **整理**：同一胶片条，强调两态勾选。工具：减帧、寻找循环帧、移出未选中、恢复未选中。右侧预览只播放**当前选中集合**。

胶片条选中态：绿勾或等价实心标记 + 正常亮度。未选中态：无勾、降低不透明度，**不得从网格里消失**。

### 5.3 步骤三：导出

左：格式与参数（第 9 节）。右：实时预览当前帧在格子里的构图，或 Sprite Sheet 的总图缩略。底部主按钮：导出 / 下载。

## 6. 抽帧合同

### 6.1 输入

- 接受：`video/mp4`、`video/webm`。其它格式失败时提示换浏览器或先转 H.264，禁止静默空工作集。
- 视频文件**默认不写入工程目录**。抽出的 PNG 才是权威素材。工程里只记：原文件名、时长、抽帧参数、裁剪矩形（归一化 0–1），便于显示，不要求下次还能打开同一 mp4。

### 6.2 裁剪与时间

- 裁剪矩形相对视频画面，整数像素，原点左上、Y 向下。
- 起止时间单位秒，精度至少 0.01s。结束必须 > 起始。
- 预估帧数：`floor((end - start) * fps) + 1` 或与参考工具一致的闭区间算法，**须在 UI 与实现用同一公式**，并在界面显示该公式结果。

### 6.3 抽样语义

第一期按**时间抽样**，不是解码器原始每一帧：

```text
t[i] = start + i / fps    （i = 0 .. count-1，最后一帧不超过 end）
```

对每个 `t`：`video.currentTime = t` → 等 `seeked` → 把裁剪区域 `drawImage` 到 canvas → PNG。

已知限制必须写在提取面板：浏览器 seek 可能落在关键帧附近，20fps 抽样一般可用；不要宣称「与 Premiere 逐帧一致」。

加分：WebCodecs 路径。没有 WebCodecs 时 seek 必须能单独跑通。

### 6.4 抽出结果

每帧一张位图，进入工作集，默认 `inWorkingSet = true`。保存到工具 `workspace/projects/<id>/frames/<index四位>.png`（或等价，路径相对仓库、正斜杠）。

## 7. 编辑合同（换色变透明 + 批量）

### 7.1 换色（必做）

交互必须是：采样 → 叠加层预览（主画布未改）→ 调参 → 应用 / 取消。

参数：

| 参数 | 语义 |
|---|---|
| 采样色 | 用户点击画面得到的 RGB（绿幕主路径） |
| 容差 | 与采样色的距离阈值，越大越多像素被当作背景 |
| 边缘清除 | 对背景掩码做收缩 / 羽化 / 去溢色，减轻绿边 |
| 替换目标 | 第一期只做 **alpha = 0**（透明），不做换成另一张图 |

预览必须用棋盘格表示透明。点应用后才写入该帧像素，并追加一条可序列化操作：

```json
{
  "type": "chromaKey",
  "x": 0.42,
  "y": 0.10,
  "color": [0, 200, 0],
  "tolerance": 8,
  "edgeCleanup": 8
}
```

坐标相对该帧宽高归一化到 0–1，便于批量时各帧尺寸一致（第一期抽出帧应同尺寸；若裁剪后同尺寸，批量直接用像素坐标也可以，但记录里仍建议归一化）。

色距建议至少用 RGB 欧氏距离或更好的 CbCr；禁止「RGB 三个通道各自相等才替换」这种一容差就烂的实现。边缘至少做掩码收缩或溢色抑制之一，否则绿边验收不通过。

不要求达到参考产品的专有换色效果；验收标准是：纯绿底卡通角色，身体不穿帮成洞，边缘无明显一圈绿，透明区为棋盘格。

### 7.2 批量应用

- 记录当前帧**已应用**的操作队列（至少含换色）。
- 「批量应用」默认目标 = 工作集内**全部选中帧**（含或不含当前帧要在确认框写清，建议包含当前帧时跳过已应用的同一条，避免叠两次）。
- 确认文案必须带数量：「将 N 个操作应用到 M 帧？」
- 回放是逐帧重跑算法，不是把当前帧像素贴到其它帧。
- 批量中途失败：已完成的帧保留结果，未完成的保持原样，并提示失败序号。禁止半写一张图。

批量适合换色；不适合把某帧上的手绘补洞当成几何对齐去贴到所有帧。若第一期只有换色，在确认框提示「请确认各帧背景色接近」。

### 7.3 撤销

单帧编辑器内至少支持一步撤销回到进入编辑器时的像素。全工作集历史不是完成门槛。

## 8. 整理合同（两态、减帧、循环）

### 8.1 两态是权威行为

工作集列表里的帧永远有：

- `inWorkingSet: true` 选中，导出与预览默认只用这些。
- `inWorkingSet: false` 未选中，**仍占着原来的序号与缩略图**。

下列操作**只允许改 `inWorkingSet`**，禁止 `splice` 掉数组：

- 减帧
- 选用某个循环方案（裁剪到循环区间）
- 单击勾选 / 取消勾选

下列操作才允许改变数组长度：

- 「移出未选中」（可确认）
- 「移出选中」（可选，第一期不做也行）
- 抽帧刚结束的初始化

移出后重排显示序号。工程里保留稳定 `id`，避免操作记录指错帧。

### 8.2 减帧

对话框：

- 当前工作集选中数量
- 每 N 帧保留 1 帧（N ≥ 2）
- 保留位置：每组第 1 张 / 每组最后 1 张
- 预计保留约 X 帧（剔除 Y 帧）——这里的「剔除」指将变为未选中，文案不要写成「删除」

算法对**当前选中序列**做分组，不是对已未选中的帧再抽一次。例如 81 张全选、N=2、留第 1 张 → 约 41 张仍选中，40 张变未选中。

确认减帧后胶片条立即反映两态。提供「撤销本次减帧」（恢复减帧前的勾选即可）。

### 8.3 寻找循环帧

用自相似矩阵（SSM），不要只比「第 0 帧和第 k 帧」一次。

1. 将每帧缩小到固定小图（建议 32×32 或 64×64 灰度 / 去透明后只计不透明像素）。
2. 算 `S[i][j]` 相似度，0–1。
3. 枚举合理长度（建议最短 8 帧、最长不超过选中数的 80%，可配置）与起点。
4. 每个候选区间 `[start, end)`：
   - **帧数** = `end - start`
   - **平滑度**：区间末帧（或 end 对应的接缝帧）与 start 的相似度，可减去区间内相邻帧突变的惩罚，映射到 0–100%
   - **覆盖率**：`帧数 / 当前选中帧数`，映射到 0–100%（与参考图 23/81≈28% 同口径）
   - **范围**：展示为「A–B 帧」（与帧数公式必须自洽；推荐半开区间，B 为接缝对照帧，并在 UI 用一句话说明）
5. 按综合分排序（平滑度与覆盖率折中，惩罚过短半步与过长烂缝），去掉高度重叠的区间，展示 Top 3–5，标签可用最优 / 次优 / 较差。
6. 列表项可点：右侧预览只播该区间，并宜显示接缝对比或「循环接缝度」。
7. 「裁剪到循环区间」：区间内 `inWorkingSet = true`，其余当前列表中的帧 `false`。

不允许只返回一个「最佳 k」且没有范围。不允许算完直接删帧。

AI 走路会有漂移，必须保留阈值 / 方案选择，禁止写死「相似度 > 0.98 才算循环」。

加分：寻找重复帧、跳变帧，同样只打标或改两态，不直接删。

## 9. 导出合同

只导出 `inWorkingSet === true` 的帧，顺序 = 胶片条从左到右、从上到下的选中顺序。

### 9.1 共用：先画 cell，再装箱

每一选中帧先渲染到 **导出分辨率 × 导出分辨率**（或自定义宽高，第一期允许正方形为主，自定义可分 X/Y）的画布：

| 参数 | 必做 | 语义 |
|---|---|---|
| 导出分辨率 | 是 | cell 宽高。预设至少 64 / 128 / 256 / 512，加自定义。默认建议 256 |
| 缩放算法 | 是 | 平滑（`imageSmoothingEnabled = true`）/ 像素风格（false） |
| 画面适配 | 建议 | 等比（默认）/ 拉伸 |
| 缩放 % | 是 | 角色在 cell 内的大小，不是改分辨率。XY 默认同步 |
| 画面偏移 | 是 | 角色在 cell 内的像素平移 |
| 填充 | 是 | 透明（默认，进游戏）/ 纯色 / 加分：边缘延伸 |

分辨率是格子；缩放是人在格子里多大。验收：同一 256×256 下 28% 与 20% 必须能看出人物大小不同、格子尺寸不变。

预览必须跟导出同一套绘制函数，禁止预览一套、下载另一套。

### 9.2 ZIP

- 每 cell 一张 PNG。
- 文件名：`001.png` 起，至少三位序号，可配置前缀。
- 打包成一个 `.zip` 下载。
- 不生成总图。

### 9.3 Sprite Sheet

- **只产出总图**（图集边长不够则多页 PNG，仍不算散图）。
- 排布：左到右，再换行。`columns = floor(atlasSize / cellW)`，`rows = ceil(frameCount / columns)`。
- 图集边长预设 512 / 1024 / 2048 / 4096 / 8192；装不下就下一页，预览显示 `1/2`。单边超过 8192 拒绝并提示减小分辨率或图集策略。
- 格间距默认 0（对齐 `Testspritesheet.png` 那种紧贴等大格）。
- 第一期**不做**去除透明边距（trim）：trim 会让格子不再等大，后续交给 Tuner 切片会裂。
- 底默认透明。纯色底可选。
- 第一期可不写 TexturePacker JSON；若写，只能当加分，且不得含盘符路径。

导出的 sheet 应能被 Tuner 用 Grid By Cell Size、Pixel Size = 导出分辨率切开。这是为后续合并预留的唯一握手，不是本期去实现 Tuner。

### 9.4 明确不做的导出

GIF、动画视频封装、半透明 GIF 抖动模拟，第一期不做。

## 10. 数据模型

`schemaVersion` 定为 `1`。改字段必须升版本。

建议磁盘布局（Git 忽略项目数据）：

```text
data/projects.json
data/projects/<project_id>/project.json
workspace/projects/<project_id>/frames/0001.png
workspace/projects/<project_id>/exports/   （可选缓存，非权威）
```

JSON 原子写入（先 `.tmp` 再 rename）。

### 10.1 登记

```json
{
  "schemaVersion": 1,
  "activeProjectId": "walk_down",
  "projects": [
    {
      "id": "walk_down",
      "label": "主角向下走",
      "kind": "video_sequence",
      "dataDir": "data/projects/walk_down",
      "workspaceDir": "workspace/projects/walk_down"
    }
  ]
}
```

`kind` 必须是 `video_sequence`，禁止写成 Tuner 的 `unity_spritesheet`，以免以后合并时撞车。

## 11. 技术约束

- 本地 Node 静态服务 + 浏览器，或纯静态亦可；第一期不要云函数。
- 抽帧、换色、SSM、拼图都在浏览器主线程或 Worker 完成。81 帧必须可交互；超过 300 帧允许变慢，但要有进度，禁止无响应死锁。
- 依赖保持少。ZIP 可用成熟库（如 `jszip` / `fflate`）。不要为第一期引入 ffmpeg.wasm（体积与 SharedArrayBuffer 成本高）。
- 路径规则与 Tuner 相同：JSON 内相对正斜杠路径，禁止 `E:\`、`Downloads`、`Assets/`。
- 界面中文。

建议仓库名：`video-sequence-packer`。端口不要占用 Tuner 的 `8787`，建议 `8788`。

## 12. 与 Spritesheet Tuner 的边界（后续再合并）

| | 本工具第一期 | Tuner |
|---|---|---|
| 输入 | 视频 | 已画好的 PNG sheet |
| 胶片条 | 独立栅格帧 + 选中态 | slice 引用 + 每帧 ms / transform |
| 编辑 | 换色、整理 | Slice、pivot、对齐、参考帧 |
| 输出 | ZIP / 等大格 Sprite Sheet | `schemaVersion: 1` 的 Unity 预备数据 |

合并时的预定握手（本期只保证，不实现对接 UI）：

1. 本工具 Sprite Sheet 的 cell 宽高 = 导出分辨率，间距 0。
2. 可选附带一份 `export-manifest.json`：`{ "cell": { "w": 256, "h": 256 }, "frameCount": 23, "columns": 8 }`（加分）。
3. Tuner 仍用现有 `importSheet` + Grid By Cell Size，Pixel Size 填 cell。

禁止为本期「方便以后」去改 Tuner 的 `schemaVersion` 或在 Tuner 里开一个隐藏的视频页。
