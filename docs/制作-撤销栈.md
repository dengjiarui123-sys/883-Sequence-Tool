## 1. 产品意图

整理和选帧会手滑。可逆操作能撤；会写毁 PNG / 删帧的操作必须先确认。  
用户确认一次不可撤销行为后，**不能再撤到确认前**，15 步额度从 0 重新累计。

规则（必须按此实现）：

- 只保存玩家 **最近 15 个** 支持撤销的操作。
- 一旦中途出现 **不可撤销且用户点了确定** 的行为，撤销保存数量重新开始计数（栈清空）。
- 用户取消确认：栈不变，数据不变。

---

## 2. 完成定义

1. 顶栏有「撤销」按钮，无记录时 disabled；有记录时可看到将撤哪一步（`title` 或按钮旁短文案，例如 `撤销：减帧`）。
2. Ctrl+Z（非输入框）执行撤销。编辑器打开时，Ctrl+Z **优先撤编辑器内预览**，不碰全局栈。
3. 只保留 **最近 15 条** 可撤销操作；第 16 条进来时丢掉最旧一条。
4. §3.1 的可撤销操作必须入栈（连续同类按 §5.2 合并）。
5. §3.2 的不可撤销操作必须先 `confirmDialog`；**只有用户点确认且操作真正执行成功后** 才 `history.clear()`。
6. 清栈后，新的可撤销操作重新从 1 记到 15。
7. 现有「撤销本次减帧」改为走同一套栈（或删除以免双栈），禁止再维护 `state.decimateUndo` 作为第二套历史。
8. 不做 redo。

## 3. 哪些可撤 / 不可撤

### 3.1 可撤销（入栈，占 15 额）

| 操作 | 撤销时恢复什么 |
|---|---|
| 胶片条勾选 / 取消勾选 | 该帧 `inWorkingSet` |
| Delete/Backspace 把当前帧标未选中 | 同上 |
| 减帧 | 全体 `inWorkingSet` 快照 |
| 全部恢复 | 全体 `inWorkingSet` 快照 |
| 裁剪到循环区间 | 全体 `inWorkingSet` 快照 |
| 裁剪框拖拽结束 | `extract.crop` |
| 起始秒 / 结束秒 / fps 改完 | `extract.startSec/endSec/fps` |
| 工程名称 | `project.label` |
| 导出侧参数改完（防抖成一条） | `project.export` 快照 |

换色编辑器内：取色、拖容差/边缘（**未点应用**）用 **编辑器局部栈**。推荐局部栈也不超过 15；关闭编辑器即丢弃，**不占** 全局 15。

### 3.2 不可撤销（必须确认；确认成功后清全局栈）

| 操作 | 现有确认 | 本窗口要补什么 |
|---|---|---|
| 开始提取（写出/替换帧 PNG） | 仅「已有帧时」有确认 | **第一次提取** 也要确认（会生成整套工作集）。 |
| 换色「应用」 | 无 | 确认「将写入该帧像素，无法撤销」。 |
| 批量应用 | 已有 | 成功后 `history.clear()`。 |
| 移出未选中 | 已有 | 成功后 `history.clear()`。 |
| 打开工程 | 无 | 若当前 `dirty` 或已有帧，确认「未保存的撤销记录将丢失」。 |
| 载入/更换源视频 | 无 | 若已有帧或 dirty，确认将替换提取设定；成功后清栈。 |

不要对播放、拖进度条、切步骤、快速保存、另存 zip、导出下载、寻找循环（只计算候选）弹确认。

### 3.3 清栈时机（严格）

```text
用户点了不可撤销操作
  → 弹出确认
  → 取消：return，history 不动
  → 确定：执行副作用（写文件 / 换工程）
  → 成功之后 history.clear()
  → 之后的可撤销操作从空栈再 push
```

执行失败（提取报错、网络失败）**不要**清栈。  
提取过程中用户取消且选择「回退到提取前」：不要 clear（等于没做成不可逆提交）。若选择「保留已抽出的帧」并 `commitBlobs` 成功：要 clear。

快速保存、布局拖拽、切 tab **不清栈、不入栈**。

## 5. 实现要点

新建 `src/history.ts`。不要把 15 条快照写入 `project.json`。刷新页面栈为空，可接受。

### 5.1 API

```ts
push(label: string, undo: () => void): void
// 超过 15 则 shift 掉最旧

undo(): boolean
// 弹出并执行最近一条；空则 false

clear(): void
// 不可撤销确认成功后调用

canUndo(): boolean
peekLabel(): string | null
```

`undo()` 之后 `state.dirty = true` 并 `persistSoon()`（与现有整理操作一致）。  
`push` / `undo` / `clear` 后更新顶栏按钮 disabled 与 title（`撤销：减帧`）。可用 `setState({ historyRev: Date.now() })` 触发 `renderShell`；**不要**把 undo 闭包数组放到 `Project` 里。

`renderShell` 里根据 `history.canUndo()` 设置 `#btn-undo` disabled，并用 `peekLabel()` 更新 title。

### 5.2 合并连续操作

下列在短时间连续触发时合成 **一条**（仍只占 15 里的 1）：

- 裁剪框：`pointerup` 时 push 一次，用 pointerdown 前的 crop 做 undo。
- fps / 起止秒 / 导出滑条 / 工程名：`change` 或约 400ms 防抖后 push；undo 回到该次开始前的值。
- 不要在 `input` 的每一个像素值都 push。

胶片条每勾一帧 = 一条（离散动作，不合并）。

### 5.3 快照方式

选中态、crop、export、label：变更前 `structuredClone`，undo 写回。  
不要把 PNG blob 放进内存当撤销。

减帧：改 `inWorkingSet` 之前 clone 布尔数组，`push({ label: "减帧", undo: () => 写回 })`。然后删除 `state.decimateUndo` 及相关 UI 双轨逻辑。侧栏「撤销本次减帧」改为调用 `history.undo()`，或删掉该按钮改用顶栏/Ctrl+Z。若保留按钮，空栈时 disabled。

### 5.4 编辑器局部撤销

编辑器打开时：

- 每次取色或改容差/边缘，往 **editorLocalStack** push（可 15 封顶）。
- `#btn-editor-undo` 与 Ctrl+Z 弹局部栈，恢复上一次预览参数并刷新预览。
- 点「应用」：确认「将写入该帧像素，无法撤销」→ `putFrame` 成功后 `history.clear()`（清 **全局** 栈），并清空局部栈。
- 点「取消」或关闭：丢局部栈，**不清** 全局栈。
- 未采样就点应用：保持现有「请先点击画面采样」提示，不要清栈。

### 5.5 Ctrl+Z

在 `src/main.ts` 现有 `keydown` 上追加：

- `ctrlKey && key === 'z'`（Windows；可同时认 `metaKey` 方便 Mac）。
- Shift+Ctrl+Z 不要当 redo，直接忽略或当普通 Ctrl+Z（不做重做）。
- `isTypingTarget` 时忽略，让输入框走浏览器默认撤销。
- `preventDefault()`。
- `state.editorOpen` → 编辑器局部 undo；否则 `history.undo()`。
- 空栈时不要乱改 status；按钮保持 disabled。

顶栏 `#btn-undo` 放在「打开工程 / 保存」附近，不要拆掉别人加的「快速保存」。

### 5.6 接入点（按文件改行为，不要重写模块）

- `filmstrip.ts`：toggle 勾选、`deselectCurrentFrame` 先 push 再改。
- `organizeUi.ts`：`applyDecimate` / `restoreUnselected` / `applyLoop` 先快照再改；`removeUnselected` 确认并删除成功后 `clear`。
- `extractUi.ts`：crop 在 pointerup 入栈；时间/fps 在 change/防抖入栈；`startExtract` 在第一次也要确认；`commitBlobs` 成功后 `clear`。确认取消则不清、不提取。
- `editorUi.ts`：见 5.4；`batchApply` 已有确认，成功后 `clear`。
- `exportUi.ts`：防抖 push `project.export`。
- `main.ts`：工程名 input 防抖 push；`openProjectFromDisk` 成功打开后 `clear`（打开前若 dirty/有帧要确认）。
- 载入视频 `attachVideo`：若已有帧或 dirty，确认后再换源并 `clear`。

`push` 的 `label` 用中文短词：`选中帧` `取消选中` `减帧` `全部恢复` `裁剪循环` `裁剪框` `抽帧参数` `工程名` `导出参数`。

## 7. 验收剧本

在浏览器里按真实用户路径过一遍：

1. 勾选 3 帧 → Ctrl+Z 三次，勾选复原；第 4 次 Ctrl+Z 无效果。
2. 减帧 → 撤销，选中态回到减帧前；顶栏按钮在空栈时灰掉。
3. 连续拖 fps 多次（防抖后应只有约 1 条）→ 一撤回到改之前的 fps。
4. 做 16 次勾选，只能撤 15 次，最早那次勾选不回来。
5. 减帧后再「移出未选中」：确认取消，减帧仍可撤；确认移出成功后，Ctrl+Z 不能回到移出前，也不能再撤减帧。
6. 移出后重新勾选新操作，可以再撤这些新操作（计数重新开始）。
7. 编辑器里调容差可撤预览；点应用并确认后，Ctrl+Z 不能恢复该帧像素。
8. 输入框里打字 Ctrl+Z 走浏览器默认，不要触发全局撤销。
9. 无帧时点「开始提取」也会出确认框；取消则不提取。
