## 1. 这个工具现在做什么

本地网页工作台。浏览器打开，素材留在本机。专门把绿幕 / 纯色底的 AI 角色视频做成可用序列帧。

用户闭环：

1. 选择 mp4 / webm，拖裁剪框，定起止时间，抽出一串 PNG。
2. 在胶片条里点一帧，用色度抠图或 BiRefNet 把背景换成透明，再把同一套操作批量回放到选中帧。
3. 减帧、寻找循环：只改胶片条的选中 / 未选中，不直接删帧。用户再决定是否把未选中帧移出。
4. 点「确认导出」后，导出 ZIP 散图，或等大格 Sprite Sheet。
5. 快速保存写入工作区；「保存工程」另存 `.vsp.zip`。刷新后从工作区恢复。

它不切片、不对齐脚底、不写 Unity。那些是旁边 **FrameTest**（Unity Spritesheet Tuner）的事。两个仓库现在分开跑。

## 2. 怎么启动

双击仓库根目录的 `启动.bat`（等同 `start.bat`）。

```bash
npm install
npm run dev
```

- 地址：http://127.0.0.1:8788 （`strictPort`，不要改去占 8787）
- 8787 是 FrameTest。两个可以同时开。
- 入口：`server/index.mjs` 起一个只听 `127.0.0.1` 的 Node，API 自己处理，页面交给 Vite middleware。
- `npm run build` 只做 `tsc --noEmit` + `vite build`，日常使用走 `npm run dev`，不依赖先 build。
- 没有测试脚本。

Git 忽略：`node_modules/`、`dist/`、`data/`、`workspace/`、`tools/ffmpeg/`。工程、帧图、BiRefNet 虚拟环境、下载的 ffmpeg 都不进仓库。

## 4. 三步里实际有的能力

### 4.1 帧提取

两种抽样，UI 里可切换，记在 `extract.mode`：

- **`time`（默认）**：浏览器 `video.currentTime` seek。公式在 `src/extractMath.ts`，UI 与实现必须同一套：`floor((end - start) * fps) + 1`，采样 `t[i] = start + i / fps`。不需要 ffmpeg。浏览器 seek 可能落在关键帧附近，不要改成宣称与 Premiere 逐帧一致。
- **`frames`**：本机 ffmpeg 按解码顺序抽出区间内全部编码帧（`-fps_mode passthrough`）。首次使用会下载到 `tools/ffmpeg/`（约 190MB）。取消提取会杀掉子进程。

裁剪矩形相对画面，归一化 0–1，原点左上、Y 向下。抽出的每一帧默认 `inWorkingSet: true`。同时写两份 PNG：

- `workspace/projects/<id>/frames/`：当前工作图（抠过的结果）
- `workspace/projects/<id>/frames-original/`：抽出时的原图

色度重算、BiRefNet、批量、还原，都从原图算。禁止在已经抠过的 PNG 上再叠一次。

重新提取会替换整套工作集，并清空撤销栈，确认框里写明无法撤销。

### 4.2 编辑

编辑器两种方法：

| 方法 | 存在哪 | 说明 |
|---|---|---|
| 色度（默认） | 浏览器 `src/chroma.ts` | 最多 8 个背景色样；色距用 YCbCr 的 CbCr；Halo 收缩 + 去溢色。旧工程的 `edgeCleanup` 仍可读：`halo = round(edgeCleanup/4)`，`despill = min(20, edgeCleanup)` |
| BiRefNet | 本机 Python | 模型 `ZhengPeng7/BiRefNet_HR-matting`，权重不进仓库。虚拟环境在 `workspace/.birefnet-venv`（已 gitignore）。界面可安装依赖、下载模型。推理走 `POST /api/matte` |

交互顺序保持：采样或调参 → 预览（主图像未写盘）→ 应用 / 取消。点应用才写该帧 PNG，并记下可序列化的 `ops`。

预览底可切换棋盘格 / 白 / 黑 / 灰，只影响看起来的底，不写入 PNG。

批量应用：把当前帧已应用的 `ops` 逐帧在**原图**上重跑，目标是工作集里选中的帧。不是把当前帧像素贴到其它帧。

「还原」把选中帧写回抽出原图，确认后清空撤销栈。

编辑器内部另有一步局部撤销（进入编辑器时的像素）。点「应用」成功后，全工作集撤销栈清空：抠图已经写进 PNG，不能再撤到应用前。

### 4.3 整理

胶片条永远两态：

- `inWorkingSet: true`：选中，正常亮度，导出和整理预览只用这些
- `inWorkingSet: false`：未选中，变暗，仍留在原来的格子上

只改两态、不改数组长度的操作：点选勾选、减帧（每 N 帧留 1 帧，留每组第一张或最后一张）、选用某个循环方案。

改变数组长度的操作：移出未选中。移出前确认，确认后清空撤销栈，然后重排 `index`。`id` 保持稳定。

循环检测在 `src/ssm.ts`：缩到 32×32，只比较不透明像素亮度，最短 8 帧，最长不超过选中数的 80%。结果是一组方案（帧数、平滑度、覆盖率、范围），选用后只改两态。选中帧少于 9 张时没有方案。

导出步骤被门闩挡住：必须在编辑整理里点过「确认导出」（`editConfirmed === true`），并且已有帧。重新提取会把 `editConfirmed` 打回 false。

### 4.4 导出

只导出 `inWorkingSet === true` 的帧，顺序为胶片条从左到右、从上到下。

每一帧先画进 `cell` 宽高的格子，再决定怎么输出。分辨率是格子；`scale` 是角色在格子里多大。预览和下载都走 `src/drawCell.ts` 的 `drawCell`，禁止预览一套、下载另一套。

- ZIP：每格一张 PNG，`fflate` 打包下载。文件名前缀来自 `export.zipPrefix`。
- Sprite Sheet：只出总图。格间距默认 0。图集边长装不下就多页。单边超过 8192 拒绝。不做 trim（trim 会让格子不等大，FrameTest 按格切开会裂）。

导出分辨率、缩放、偏移、等比/拉伸、平滑/像素、透明或纯色填充，都已有。

### 4.5 保存

两套保存，不要合成一个按钮：

| 按钮 | 行为 |
|---|---|
| 快速保存（Ctrl+S） | `persistNow()`，只写 `data/projects/<id>/project.json`。帧 PNG 在编辑时已经单独 PUT |
| 保存工程 | Windows 另存对话框，写出 `.vsp.zip` |

`.vsp.zip` 里是便携路径：`project.json` + `frames/0001.png` …。包内 JSON 的 `frames[].file` 是 `frames/xxxx.png`，打开时再改回 `workspace/projects/<id>/frames/xxxx.png`。

包里**没有** `frames-original/`。从 zip 打开的工程，像素是抠过的工作图；没有原图的帧不能再按原图重跑色度 / BiRefNet。这是已知限制。

工作区 JSON 禁止盘符、`Downloads`、Unity `Assets/`。`.vsp.zip` 的绝对路径只存在 `data/last-project-file.json`（本机最近一次保存位置），不写进 `project.json`。

打开工程：优先 PowerShell 对话框；对话框失败时退回浏览器 `<input type="file">`。

撤销栈只在内存里，最多 15 步。会毁掉 PNG 或删帧的操作（重新提取、应用抠图、移出、还原、打开另一份工程）在用户确认后 `history.clear()`。布局拖拽和快速保存本身不入栈。

## 5. 磁盘与 JSON

```text
data/projects.json                          登记与 activeProjectId
data/projects/<id>/project.json             权威工程
data/last-project-file.json                 最近一次 .vsp.zip 的本机路径
workspace/projects/<id>/frames/0001.png     工作图
workspace/projects/<id>/frames-original/    抽出原图
workspace/.birefnet-venv/                   BiRefNet 虚拟环境
tools/ffmpeg/                               按需下载的 ffmpeg / ffprobe
```

JSON 原子写：先 `.tmp` 再 rename。

`kind` 必须是 `video_sequence`。禁止写成 FrameTest 的 `unity_spritesheet`。`schemaVersion` 现在是 `1`，不兼容的字段变更要升版本，禁止悄悄改语义。

登记项：

```json
{
  "schemaVersion": 1,
  "activeProjectId": "seq_…",
  "projects": [
    {
      "id": "seq_…",
      "label": "未命名序列",
      "kind": "video_sequence",
      "dataDir": "data/projects/seq_…",
      "workspaceDir": "workspace/projects/seq_…"
    }
  ]
}
```

`project.json` 的形状以 `src/types.ts` 的 `Project` 为准。相对第一期合同，已经多出来、必须保留的字段：

- `extract.mode`: `"time" | "frames"`
- `extract.sourceFps`: 编码帧模式探测到的源帧率
- `editConfirmed`: 是否已点「确认导出」
- `frames[].ops[]` 联合类型：`chromaKey`（可带 `colors` / `halo` / `despill`）或 `birefNet`
- `export.fillColor`、`export.zipPrefix`
- `export.smoothing`: `"smooth" | "pixel"`

权威像素在 PNG 上。`ops` 是已应用操作的记录，用来批量回放；刷新后直接显示 PNG，不靠重放 ops 才能看见抠图结果。

## 7. 和 FrameTest 的边界

FrameTest 仓库：`E:\AI_Tool\FrameTest`。产品名 Unity Spritesheet Tuner。端口 **8787**。`kind` 是 `unity_spritesheet`，同样 `schemaVersion: 1`，但是**另一套 JSON**。

| | 本工具 | FrameTest |
|---|---|---|
| 输入 | 视频 | 已经画好的 spritesheet PNG |
| 工程 | `video_sequence`：帧列表 + `inWorkingSet` + `ops` | `unity_spritesheet`：sheet、切片池、profile / animation、每帧 ms 与 transform |
| 编辑 | 抠透明、减帧、找循环 | Slice、pivot、参考帧对齐 |
| 输出 | ZIP 或等大格 Sprite Sheet | 第一期只存自己的项目；第二期写 Unity Multiple Sprite `.meta` |
| 服务 | `server/index.mjs` :8788 | `tools/editor/server.js` :8787 |

现在两套不要合并成一个 App，不要共用一份 `project.json`，不要把本工具的页面写进 FrameTest 的 `tools/editor`，也不要在本仓库里做切片或写 `.meta`。

以后集成时，预定的握手是这张图，不是合并 schema：

1. 本工具 Sprite Sheet 的格子等大，格间距 0，格子宽高 = 导出分辨率（`export.cell`）。
2. FrameTest 用现有导入 + **Grid By Cell Size**：Pixel Size = 这个 cell，Offset = 0，Padding = 0。实现在 `FrameTest/tools/slicer/grid.js` 的 `gridByCellSize`。
3. 空格子不要靠 trim 去掉，否则格网对不齐。FrameTest 的 Keep Empty Rects 由那边决定。
4. 可选、尚未做：导出时附带 `export-manifest.json`，例如 `{ "cell": { "w": 256, "h": 256 }, "frameCount": 23, "columns": 8, "padding": 0 }`。做的时候路径仍然用相对正斜杠，不要写盘符。

FrameTest 第一期、第二期合同在它自己的 `docs/`。读本仓库时不必实现那两份；要对齐切片语义时再打开 `grid.js` 和它的第一期说明第 6 节。

## 8. 后续打算（先记在这里，等作者开口再做）

作者认为本地工具这一阶段已经比较完整。下面两件是下一阶段，**不要在普通修 bug / 小改里顺手开工**。

### 8.1 网页版

目标是同一套三步（提取 → 编辑整理 → 导出），能在浏览器里用，而不是只能双击本机 bat。

已经能留在浏览器里的：按时间抽样、色度抠图、胶片条、减帧、SSM、`drawCell` 导出、用 `fflate` 打 ZIP、用文件选择框打开 zip。

绑在这台 Windows 本机、网页版必须换掉或做成可选服务的：

- `server/fileDialog.mjs` 的 PowerShell 对话框
- `tools/ffmpeg/` 与编码帧提取
- BiRefNet 的本机 Python 虚拟环境、CUDA、模型下载
- 把工程写进仓库旁的 `data/`、`workspace/`
- 只听 `127.0.0.1` 的服务

网页版优先沿用 `.vsp.zip` 作为用户手里的工程文件（打开 zip 的浏览器回退路径已经有了）。工作区目录是本地模式的缓存，不是用户必须看见的格式。

做网页版时保持 `kind: "video_sequence"` 和 `schemaVersion`。能在浏览器完成的路径继续放在 `src/`，不要为了上线把色度、SSM、拼图改写成必须有服务器。编码帧和 BiRefNet 可以仍是「有服务才出现」的能力。

### 8.2 和 FrameTest 接成一条流水线

期望的用户路径：

```text
883 Sequence Tool：视频 → 抠透明 → 整理 → 等大格 Sprite Sheet
        ↓
FrameTest：按 cell 切开 → 对齐 / pivot / 参考帧 → （第二期）写入 Unity
```

集成时两套 `kind` 仍然分开。本工具负责把选中帧画成 FrameTest 能按格切开的图；FrameTest 继续拥有切片、对齐和 Unity。不要把视频抽帧页做进 FrameTest，也不要在本工具里做 Sprite Editor。

在作者明确说「开始做网页版」或「开始接 FrameTest」之前，保持现在的本地双端口结构。

## 9. 改代码时守住的规则

- 界面文案中文。
- 依赖保持少。现有运行时依赖只有 `fflate` 和 `vite`。不要为了网页版或对齐参考产品，把 FramePacker 的源码、WASM、`_FP.html` 工程包拷进仓库。
- 抽帧公式、两态、`drawCell` 预览与导出共用、从原图重跑 `ops`，这四条是行为合同。改算法要同时改 UI 上的数字，让用户看到的预估和结果一致。
- 减帧和循环只改 `inWorkingSet`。只有「移出」和重新提取可以改变 `frames` 长度。
- `project.json` 里只用相对正斜杠路径。
- 栏宽留在 `localStorage`。撤销栈留在内存。
- 端口保持 8788。
- 历史制作说明（`docs/制作-*.md`、第一期合同）是当时某个窗口的范围，不是当前 bug 列表。和代码冲突时，以代码和本文为准，并在本文补一句，而不是把功能改回旧合同。
