## 1. 产品意图

设计师要看懂「每秒抽几张」，并在左侧预览里只播将要提取的那一段。  
另外要能一键把当前工程参数写入工作区（不是另存 zip），并看到「保存成功 + 时刻」。

对应需求：

1. 抽帧选项改成「每秒从视频中提取多少个画面」这种人话。
2. 右侧起始秒 / 结束秒改了以后，左侧视频预览的时间区间必须一致。
3. 追加「快速保存」：保存当前工程调参，成功 toast 带保存时间。

## 2. 完成定义

1. 抽帧滑条主文案表达「每秒抽取多少帧」，并有一句人话说明「每秒从视频中提取多少个画面」。
2. 预估帧数用「时长 × 每秒帧数 ≈ N 帧」这种说法；现有公式可留作次要提示，不要当主文案。
3. 改右侧起始秒 / 结束秒后，左侧进度条的可拖范围、播放区间、时间数字立刻变成同一段。
4. 播放不会播到区间外；若播放头在区间外，自动 seek 进区间。
5. 顶栏有「快速保存」，调用现有 `persistNow()`，不打开系统另存对话框。
6. 快速保存成功后出现 toast，文案含本地时间（例如 `已保存 14:32:08`），约 2.5s 后消失。
7. 顶栏原「保存工程」仍是另存 `.vsp.zip`。可用 title/hint 标明「导出工程包」，不要删。
8. 修改起始/结束/fps 后工程标为 dirty（现在这三项改了不会 dirty，这是 bug，要修）。

## 5. 实现要点

### 5.1 抽帧文案

建议结构（class 名可自定，语义不要变）：

- 标签：`每秒抽取 <span id="fps-val">20</span> 帧`
- 说明：`每秒从视频中提取多少个画面`
- 预估：`预估 <b>N</b> 帧　（区间 T 秒 × 每秒 N 帧）`
- 原公式可写成更小的 hint，或放在 `title` 里。

`refreshExtractStats()` 同步这些数字。抽帧仍走 `estimateFrameCount` / `sampleTimes`。

`refreshExtractStats` 在写入 `project.extract.*` 时设 `state.dirty = true`（有 project 且值确实变了再标 dirty，避免无意义刷）。

### 5.2 预览区间同步

新增一个函数（例如 `applyPreviewRange()`），在以下时机调用：

- 起始秒 / 结束秒 `input`
- 载入视频 `attachVideo` 完成
- `syncExtractFieldsFromProject`

令 `start` / `end` 为右侧当前值，夹紧到 `[0, duration]`，且保证 `end > start`（无效时不要把进度条搞死，可暂用整段时长）。

行为：

1. `#video-scrub.min = start`，`.max = end`，`step` 保持细粒度（如 0.01）。
2. 若 `video.currentTime` 在区间外：小于 start 则 seek 到 start；大于 end 则 seek 到 end。
3. `#video-time` 必须反映区间，不要再把整段片长当「总时长」。推荐：
   - `formatTime(current) / formatTime(end)`，或
   - `formatTime(current) / formatTime(end)` 再在旁边标区间时长  
   只要用户能看出总长已经变成截取段。
4. `timeupdate`：若正在播放且 `currentTime >= end - 0.01`，`pause()`，钉在 `end`。
5. 点 `#btn-play` 或空格触发的 `toggleVideoPlay`：准备 `play()` 时若当前不在区间内，先 seek 到 `start`。
6. 拖进度条仍直接改 `video.currentTime`，但 min/max 已经限制在区间内。

原生 `<video>` 没有入出点，用现有 `timeupdate` 夹住即可，不要换播放器。

### 5.3 快速保存 + toast

- `index.html` 顶栏 `#btn-save` 旁加 `#btn-quick-save`，文字「快速保存」。
- `#btn-save` 加 `title="导出 .vsp.zip 工程包"` 或短 hint，避免和快速保存混淆。不要改按钮文字到让用户找不到「保存工程」。
- `src/dom.ts` 新增并 export `showToast(message: string)`：固定右上或底部中央，不打断操作，约 2.5s 消失；重复调用重置计时。
- `index.html` 加 toast 容器（例如 `#toast`）。
- 点击「快速保存」或 **Ctrl+S**（`isTypingTarget` 时不要拦截）：`await persistNow()`，成功后 `showToast(\`已保存 ${hh:mm:ss}\`)`。
- 时间用本地时分秒，例如 `14:32:08`。数据源用 `persistNow` 写入的 `state.lastSavedAt`。
- 底部 `#save-state`：dirty 时「有未保存更改」；否则若有 `lastSavedAt` 显示 `已保存 14:32:08`；都没有则「未保存」。这段在 `src/main.ts` 的 `renderShell` 里改即可。
- 用户取消另存 zip（`saveProjectFile` 取消）不要误弹「已保存」toast。
- Ctrl+S 只绑快速保存，不要触发 `#btn-save` 的系统对话框。

`persistNow` 里已有 debug ingest 日志，不要删、不要「清理」。可以在成功路径上不重复发明状态字符串；toast 由调用方或 `persistNow` 末尾调 `showToast` 均可，但要避免一次保存弹两次。

无 project 时快速保存应给出明确 status，不要空点无反应。

## 6. 验收

在浏览器里按真实用户路径过一遍（本机 `npm run dev`，默认 http://127.0.0.1:8788）：

1. 打开帧提取，fps 滑条旁能读懂「每秒抽几张」；改滑条时预估帧数跟着变，主文案不是那条 floor 公式。
2. 载入视频后把起始改为明显大于 0、结束改为明显小于片长：左侧进度条拖不到片头/片尾，时间总长变成截取段，播放到结束秒停止。
3. 再改起始/结束，左侧区间立刻跟上，播放头若在外面会被拉回来。
4. 改 fps 后底部出现「有未保存更改」；点快速保存，toast 带时刻，dirty 消失，状态栏也有时刻。
5. Ctrl+S 同样快速保存，不弹系统另存框。
6. 点「保存工程」仍出系统另存框。取消另存时不应出现成功 toast。
