## 1. 产品意图

设计师处理的是 **绿幕 / 近绿幕的 AI 卡通人物序列**。现在编辑器只有「点一次采样 + RGB 欧氏容差 + 一条边缘清除」。结果是：

- 幕布有阴影、压缩块、另一块略偏的绿 → 留下残绿。
- 把容差拉大 → 衣服、描边、头发被打成洞。
- 棋盘格上看不清残绿，误以为抠干净了。

本期只解决这件事：**残绿能去掉，身体不明显穿帮。**

方法分两级，都在同一编辑器里，用户先用色度；色度会打洞才换 BiRefNet。

| 级 | 方法 | 解决什么 | 不解决什么 |
|---|---|---|---|
| 1（必做，默认） | 改进色度 | 多块绿、阴影绿、绿边 | 和人物颜色缠在一起的杂底 |
| 2（必做，可选方法） | BiRefNet | 色度拉完仍残、或一拉就穿帮 | 火焰/闪电等亮部 VFX（不做 Luma） |

白 / 黑 / 灰只做 **预览底**，用来显残绿和破洞，不参与抠图像素运算。

## 2. 完成定义

全部成立才算本期完成。不要把「加了一个 BiRefNet 按钮但色度还是一块绿」当成完成。

### 2.1 色度（默认路径）

1. 编辑器可 **连续点击画面添加多个背景色样**，上限 **8** 个唯一 RGB；可单独删除某个色样或清空。
2. 色距改为 **YCbCr 的 CbCr**（忽略亮度为主）。绿幕上的暗绿阴影必须能被抠掉，且不要求把容差拉到打穿衣服。
3. 「边缘清除」拆成两个滑杆（见 §6.2）：**Halo 收缩**、**去溢色**。原先一条 `edgeCleanup` 映射规则见 §6.2。
4. 预览底可切换：**棋盘格 / 白 / 黑 / 灰**。残绿在白底或灰底上必须能看出；破洞在黑底或白底上必须能看出。预览底只改画布后面的颜色，不写入 PNG。
5. 交互仍是：采样 → 预览（主图像未写）→ 调参 → 应用 / 取消。点应用才写该帧像素。
6. 已应用的色度操作可 **批量回放到选中帧**，回放的是多样本 + 新色距，不是贴图。

### 2.2 抽出原图

7. 新抽出的帧必须另存一份 **未抠原图**。编辑器打开时始终对原图做预览。应用只覆盖「工作帧 PNG」，不覆盖原图。
8. 旧工程没有原图时：第一次打开编辑器，把当前工作帧复制为原图（best-effort），并在状态栏提示「本工程无抽出原图，已用当前帧作为原图」。

### 2.3 BiRefNet（色度不够时）

9. 编辑器方法切换含 **色度 | BiRefNet**。切到 BiRefNet 不丢色度色样（只是预览改走 matte）。
10. BiRefNet 对 **原图** 出一张 alpha，前端用阈值 / 羽化做即时预览（拖滑杆不得每帧重跑模型）。
11. 权重不进 git；第一次选用时先检查本地缓存，缺失则弹窗确认后再下载。取消则留在色度。推理时 `local_files_only`，禁止静默联网。
12. BiRefNet 的应用 / 批量同样写工作帧 PNG、追加 `ops`。批量中途失败：已完成保留，失败序号提示，禁止半写一张图。

### 2.4 验收画面（必须过）

用「纯绿底卡通角色、幕布带一点阴影或不匀」的序列：

- 色度多样本：点主绿 + 点阴影绿，身体不穿帮，脚底 / 腿之间 / 画布边的残绿在 **白底预览** 下基本消失。
- 边缘无明显一圈绿（去溢色要起作用）。
- 同一套操作批量到邻帧，邻帧幕布接近时结果稳定。
- 故意留一帧「绿和衣服很近、色度会打洞」：切 BiRefNet 后衣服保住，幕布去掉。

## 4. 现状（必须对着改）

现有实现：`src/chroma.ts` 的 `applyChromaKey`。

- 只吃 **一个** `op.color`。
- 色距是 RGB 欧氏距离 `/ √3`，阴影绿的亮度差会被算进容差，逼用户两头难。
- `edgeCleanup` 一条滑杆同时做：掩码膨胀、盒模糊羽化、按绿通道去溢色。想去残边时容易啃主体。

- `applyEditor` / `batchApply` 读的是 **当前工作帧 PNG**（已抠过还会叠）。
- `FrameOp` 只有 `chromaKey`。

这些都要改。不要另起一套滤镜却留着旧函数给批量用——预览和批量必须走同一套 `applyChromaKey` / `applyBirefNet`。

## 6. 色度合同

### 6.1 多样本

点击画面：在现有色样里追加该像素 RGB。已有近似色（建议 RGB 各通道差都 ≤ 2）则不重复加。满 8 个时提示「最多 8 个背景色」，不再追加。

侧栏展示色样条：色块 + 删除。清空后预览回到未抠。

没有色样时不跑抠图（和现在「未采样」一样）。

### 6.2 参数

| 控件 | 语义 | 建议范围 | 默认 |
|---|---|---|---|
| 色样 | 背景 RGB 列表 | 1–8 个 | 空 |
| 容差 | CbCr 距离阈值 | 1–80 | 24 |
| Halo 收缩 | 背景掩码膨胀半径，收掉一圈残边 | 0–12 | 2 |
| 去溢色 | 保留像素里过绿的通道往回拉 | 0–20 | 8 |
| 预览底 | 棋盘格 / `#FFFFFF` / `#000000` / `#9E9E9E` | 四选一 | 棋盘格 |

旧滑杆 `edgeCleanup` 迁移：已存工程 `edgeCleanup` → `halo = round(edgeCleanup/4)`，`despill = min(20, edgeCleanup)`。预览与批量读新字段；写盘用新字段。读到只有 `edgeCleanup` 的旧 `ops` 必须仍能批量（兼容映射，不要丢操作）。

### 6.3 色距（必须按此语义）

对每个色样把 sRGB 转 YCbCr（可整数近似）：

```text
Y  =  0.299 R + 0.587 G + 0.114 B
Cb =  B - Y
Cr =  R - Y
chromaDist(p, s) = hypot(Cb_p - Cb_s, Cr_p - Cr_s)
pixelDist = min(chromaDist(p, s) for s in samples)
```

`threshold = (tolerance / 100) * 255`。`pixelDist <= threshold` 视为背景。

禁止再把 RGB 欧氏距离当主色距。禁止「三通道各自相等才替换」。

已透明像素（原图 alpha=0）保持透明，不要把隐藏 RGB 重新抠成可见。

### 6.4 边缘

1. 得到背景掩码。
2. Halo > 0 时对背景掩码做膨胀（沿用现有 `dilateMask` 即可）。
3. 用很小的盒模糊做 1px 级羽化即可（不要再把 Halo 和模糊绑死成一条超强模糊）。
4. 去溢色：对 **保留** 且 `G > max(R,B)` 的像素，按去溢色滑杆压绿、略补红蓝（可留现有 despill 公式，改成只吃 `despill` 而不是 `edgeCleanup`）。
5. 几乎透明的像素仍把 RGB 置 0，避免导出白边。但 **算法输入始终是原图**，置 0 只发生在写出的工作帧上。

### 6.5 操作记录

```json
{
  "type": "chromaKey",
  "x": 0.42,
  "y": 0.10,
  "color": [0, 200, 0],
  "colors": [[0, 200, 0], [12, 140, 48]],
  "tolerance": 24,
  "halo": 2,
  "despill": 8
}
```

- `color` 保留：等于 `colors[0]`，旧代码 / 旧工程能读。
- `colors` 缺省时视为 `[color]`。
- `x,y` 仍是第一次采样的归一化坐标；多样本不要求每颗都存坐标。
- `opsEqual` 必须比较 `colors`、`tolerance`、`halo`、`despill`（含旧字段映射后的值），避免批量叠两次。

## 7. BiRefNet 合同

### 7.1 何时用

侧栏方法切到「BiRefNet」：适合色度多样本后仍残绿，或容差一加身体就破。

不自动在色度之后串跑 BiRefNet。用户显式选择。两种方法不要在同一帧 `ops` 里各写一条还叠着抠——应用 BiRefNet 时，该帧预览以原图 + BiRefNet 为准；若该帧以前只有 chromaKey，批量「把当前帧操作应用到选中帧」只回放当前方法那一条（见 §9）。

### 7.2 模型

- 只用 **BiRefNet HR-matting**（`ZhengPeng7/BiRefNet_HR-matting`），revision **钉死**在代码常量里，升级必须改常量。
- 显存不够允许文档写明改 lite；本期 UI 不必做模型下拉。
- 推理输入按原图比例缩放到模型边长（建议 1024，大图可按面积自适应，上限 2048），输出 alpha 再双线性拉回原图像素尺寸。**不要 letterbox 出黑边再当背景。**

### 7.3 预览

1. 打开编辑器或切到 BiRefNet：对当前原图请求一次 matte（带进度）。
2. 返回的是原尺寸 alpha（或浮点 mask）。
3. 前端滑杆：

| 控件 | 语义 | 默认 |
|---|---|---|
| 阈值 | 低于此值的 alpha 视为背景 | 0.5 |
| 羽化 | 对 alpha 做小半径模糊 | 1 |

拖这两条只重画，不请求模型。换帧、关编辑器再开，才重新推理。

失败：状态栏写清原因（未安装 / 未确认下载 / CUDA 失败已回退 CPU / 超时）。预览保持原图。

### 7.4 写出

`最终 alpha = smoothstep(模型alpha, 阈值, 羽化)`，乘到原图 RGB。不要先把 BiRefNet 结果合成到白底再抠。

### 7.5 操作记录

```json
{
  "type": "birefNet",
  "model": "hr-matting",
  "threshold": 0.5,
  "feather": 1
}
```

批量回放：每帧对 **该帧原图** 跑同一模型（可按帧缓存到内存，不要把 matte PNG 写进工程除非你用来加速且 gitignore）。阈值和羽化必须逐帧重做。

### 7.6 运行时

优先顺序（实现选一条做完即可，不要三条都做）：

1. **独立 Python worker**（本机已有 CUDA 时最快）：Node 把原图 PNG 交给 worker，收回 alpha PNG。
2. 或 `onnxruntime-node` + 预转换 ONNX。

要求：

- 可选依赖，不装也能用色度。
- 首次切到 BiRefNet：检查缓存 → 确认下载 → 再推理。
- Windows 路径、中文工程名必须能跑。
- 不要在 Vite 前端 bundle 里塞数百 MB 权重。

## 9. 批量合同

- 「批量应用」仍针对 **当前帧已应用的 ops**，目标 = 选中帧。
- 当前帧若最后一次应用的是 `birefNet`，批量只回放尚未拥有 **相等** `birefNet` 的目标帧。
- 当前帧若是 `chromaKey`，批量只回放色度（含多样本）。
- 确认框必须带数量，并提示：「色度：请确认各帧幕布接近。BiRefNet：将逐帧推理，可能较慢。」
- 进度条复用现有 `#batch-progress-root`。BiRefNet 批量禁止卡住 UI：每帧 `await` 让出主线程。
- 回放输入 = 目标帧原图。禁止读已经抠过的工作帧当输入。

## 10. 撤销

不借：Luma 补亮部、主体保护预设、CorridorKey、十种组合模式。他们后来也把组合模式收成互斥方法。我们保持 **色度 | BiRefNet** 两选一。
